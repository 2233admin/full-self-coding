# End-to-end smoke test: native worktree mode with a real agent

Date: 2026-10-25. Machine: Windows Server 2025, `claude` CLI logged in, no Docker involved.

## Setup

A scratch repository with one commit and no `origin` remote:

```
math_ops.py   def add(a, b): # TODO: return the sum of a and b / pass
text_ops.py   def shout(s):  # TODO: return s upper-cased with "!" appended / pass
```

Command (from inside the repository):

```
FSC_MAX_TASKS=2 FSC_MIN_TASKS=2 bun packages/cli/src/index.ts run
```

## Result of the last run

- Analysis found 2 tasks, one per file.
- Two `claude` agents ran in parallel, each in its own git worktree (exec phase: 77 s).
- Both commits were cherry-picked onto `main` at tier 1 (no conflicts), exit code 0.
- `git log`: `feat: implement add(a, b) in math_ops`, `feat: implement shout() in text_ops` on top of `init`.
- `python -c "assert add(2,3)==5 and add(-1,1)==0 and shout('hi')=='HI!'"` passes.
- Worktrees and task branches were removed after the merge; only `__pycache__/` (from the check above) was left untracked.

Not measured: the first, analysis phase of the final run. Total wall clock of that run was 16 min 10 s, against 38 s to 2 min for earlier runs with the same prompt. Cause not investigated (could be API queueing); exec phase was 77 s.

## What it took to get here (all fixed in the same PR)

Four earlier runs failed. Each failure was a real defect, not a flaky environment:

1. **No `origin` crashed the CLI** with a source-code stack trace, although native mode never uses a remote.
2. **The analysis step was Docker-only** (container, `apt-get`, copying `~/.ssh` into it). Added a native analyzer that runs `claude` in a throwaway detached worktree.
3. **A failed analysis cleanup hid the result** (`EBUSY` on Windows). Cleanup is best effort now.
4. **Agent name `claude-code` fell back silently to `opencode`** (not installed). Names are normalized; unknown names are an error.
5. **The `claude` builder passed `--cwd`**, a flag that does not exist, and no permission mode, so unattended edits could not work.
6. **False success.** With no changes made, the old reporter printed "ALL TASKS COMPLETED SUCCESSFULLY, 100%". A run that changes nothing is now a failure, spawn errors are reported, and the exit code is 1 when anything is not merged.
7. **The native path never merged anything.** The CLI used the Docker-era solver plus `CodeCommitter`. It now uses `UnifiedScheduler` (worktree per task, then ordered merge).
8. **The scheduler collided with itself.** It leased a pool slot and ran `checkout -b fsc/<task>`; `LocalExecution` then ran `worktree add -b fsc/<task>` and failed with "branch already exists" on every task. The unused pool is gone from the execute path.
9. **Untracked files blocked merges** ("working tree is dirty") although they never affect a cherry-pick. Only tracked changes count now (TS and Rust sequencers, with golden scenarios).
10. Stale `fsc/<task>` branches from earlier runs: removed when they hold no unmerged commits; refused with a clear message when they do.

## Limits of this test

- One repository, two independent tasks, one agent type (`claude-code`). No conflicting tasks, no failing agent, no more than 2 agents at once.
- Other agents (`gemini`, `codex`) are mapped but untested; `--cwd` is still present in their builders and may be wrong.
- Worktrees are created next to the repository (`<repo>-fsc-<task>`), not inside it.
- Scale: see issue #10. Nothing here says anything about 100 or 1000 agents.
